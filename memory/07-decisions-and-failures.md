## 二、尝试过但失败的方案

| # | 方案 | 失败原因 |
| :--- | :--- | :--- |
| 1 | `rknn.accuracy_analysis(target='rk3588')` | **必须 adb 连物理开发板**，本机无板 → `RuntimeError: no devices/emulators found`。该接口无"模拟器逐层"模式 |
| 2 | `hybrid_quantization_step1(proposal=True)` | 在 YOLOv8 上崩：`KeyError: '/model.22/dfl/Softmax_output_0_sw'`（内部映射缺失）。去掉 `proposal` 即正常 |
| 3 | 先导出 `.rknn` 再另开进程加载推理 | `load_rknn()` 加载的模型**无法在模拟器推理**。必须同进程内 `step2 → init_runtime → inference` |
| 4 | 保敏感 14 层 / 保整个检测头 51 层 | **完全无效**，仍 0 检测。逐层误差指标误导了修复方向 |
| 5 | 换校准集（182→500 张 val2017） | **未能挽救纯 INT8**（仍 0 检测）。属结构性问题，非校准集代表性不足 |
| 6 | 把 `Constant` 节点写进 `custom_quantize_layers` | 报 `Invalid operands name '/model.22/Constant_12_output_0'`，需过滤掉 |
| 7 | 用 `git add .` 推 aiVault | 会连带 `inbox/` 下 19 个**未经 ingest 筛选**的日期目录。已按用户选择接受此风险 |
| 8 | 直接跑 `push_ai.bat` | 结尾有 `pause`，非交互环境会卡死。改用等效三条 git 命令 |

## 三、方法论教训

1. **逐层误差指标不能直接用于推导修复方向**。
   cosine/SNR 把检测头标为最敏感，但保检测头完全无效。
   真正的病因在输出张量的**范围冲突**上，与"哪层误差大"不是一回事。
2. **按名字前缀筛层是危险操作**。
   `output0-*` 不带 `/model.` 前缀，被"主干"集合顺带纳入，
   制造了"保主干有效"的假象（见 `06-session-log.md` §三）。
3. **"看起来合理的归因"必须用消融实验验证**。
   本次连续推翻了两次自己的归因（检测头 → 主干 → 输出层）。
